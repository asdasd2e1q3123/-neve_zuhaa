# День 17. DNS: как домены превращаются в IP-адреса

Ну вот возьмем ситуацию, вы хотите зайти на сайт **nevezuha.gay**, но к какому серверу подключиться твое устройство не понимает. Ведь устройства в сети взаимодействуют через айпи адреса, а не привычные нам домены

За преобразование доменов в айпи адреса отвечает DNS

## 1. Что такое DNS?

Система доменных имён (DNS) - это телефонная книга интернета. Люди получают доступ к информации в сети с помощью доменных имён, например nytimes.com или espn.com. Веб-браузеры же взаимодействуют с ресурсами через IP-адреса. DNS преобразует доменные имена в IP-адреса
Взято и переведено с - https://www.cloudflare.com/en-gb/learning/dns/what-is-dns/?r=1

Вот возьмем самый базовый пример, google.com переводится с понятного нам домена в понятный для компьютера айпи адрес, а именно 142.250.185.14

## 2. Как работает DNS?

Когда ты вводишь домен в браузер, происходит несколько действий:

1. **Проверка кэша.** Сначала браузер проверяет собственный DNS-кэш, затем кэш операционной системы, если ничего не находит то идет на 2 этап
2. **DNS-запрос.** Если нужной записи нет, компьютер обращается к DNS-резолверу(про это далее)
3. **Поиск адреса.** Резолвер при необходимости обращается к другим DNS-серверам, чтобы найти нужную запись
4. **Получение ответа.** DNS возвращает айпи адрес домена
5. **Подключение.** Браузер использует полученный айпи адрес для подключения к серверу сайта

## 3. Какие DNS-серверы существуют?

- **DNS Resolver** - принимает запрос пользователя и организует поиск нужной записи
- **Root DNS Server** - указывает, где искать информацию о домене верхнего уровня
- **TLD DNS Server** - отвечает за домены верхнего уровня, например `.com`, `.org`, `.ru`, ну короче все то, что вы встречаете каждый день
- **Authoritative DNS Server** - хранит DNS-записи конкретного домена и возвращает авторитетный ответ
 
**Самое частое, что встречается это dns resolver**

## 4. Основные типы DNS-записей

  Существует разные типы записей днс, про это часто спрашивают на собесах:

A - связывает домен с IPv4 адресом( про такие айпи говорил раньше)

AAAA - связывает не поверите домен с IPv6 адресом

CNAME - создает что-то типо псевдонима для другого доменного имени. Ну вот возьмем основной домен 
nevezuha.com, а псевдонимом является shop.nevezuha.com

MX - указывает почтовые серверы домена

NS - указывает днс сервера, которые обслуживают домен

TXT - это днс запись, которая позволяет хранить доп текстовую информацию о домене, например какой владелец у этого домена

## 5. Какой порт использует DNS?

В предыдущем посте говорил про порты и упоминал DNS, если не забыли то у него по умолчании 53 порт:

53/UDP - нууу он используется для большинства обычных запросов dns
53/TCP - он нужен например для ответов, которые не помещаются в UDP

Также существуют защищённые варианты dns, например DoH (DNS over HTTPS) и DoT (DNS over TLS)

## 6. Практика: проверяем DNS самостоятельно

На вашем любимом линуксе можно использовать несколько команд для работы с DNS

**Узнать айпи адрес домена:**

`nslookup google.com`

**Получить подробную информацию о DNS-записи:**

`dig google.com`

**Посмотреть DNS-записи определённого типа:**

`dig google.com MX`

**Получить айпишник домена без лишней информации**

`dig +short google.com`

Если вы раньше не работали с этими командами, то смотрите на секцию ANSWER SECTION, так будет легче читать вывод команды

## 7. Почему DNS важен в кибербезопасности?

Короче, существует много атак на dns, взял 3 самых частых:

DNS Tunneling - это передача данных через dns-запросы, ну она используется для обхода сетевых ограничений и передачи информации. Его легко найти в логах, вот например **as8sajfsaf83sfjj21ii9fo0sdvjff**, вот видите чото такое, то это скорее всего dns tunneling

**DNS Spoofing** - это подмена dns-ответов, из-за которых пользователь может попасть на поддельный сайт, а это уже страшно. Его можно найти по несоответствии айпи адреса домена ожидаемому значению, неожиданное изменение dns ответов, несколько разных ответов на одинаковые запросы

**DNS Hijacking** - перенаправление dns-запросов на другой dns-сервер, чтобы изменить адреса, возвращаемые пользователю, ну его можно найти через изменение используемого dns-сервера, появление новых и неизвестных dns-резолверов, неожиданное перенаправление dns запросов
